# Rasc Web — Agent Instructions

## Product state

The Rasc macOS app is considered feature-complete for the current phase.

Do not propose app features while working on the website unless explicitly asked.

## Source priority

When sources disagree, follow:

1. approved docs in /docs
2. actual Rasc application behavior and visual system
3. DESIGN.md
4. reference notes in /references
5. general design/frontend conventions

## Hard constraints

Do not:

- reposition Rasc as an AI notes app;
- reposition Rasc as a knowledge-management system;
- invent features not present in the app;
- recreate app UI in HTML when a real product asset exists;
- introduce generic AI gradients, glow, spheres, sparkles or chatbot visuals;
- turn the landing into a SaaS feature grid;
- change the approved landing information architecture without explicit approval;
- copy reference branding, typography, colors or components wholesale.

## Brand

Brand symbol = Rasc identity.

Thinking Orb = semantic shaping/state language.

They are not interchangeable.

## Visual direction

The website is predominantly light and warm/editorial.

Orange = primary actions.

Violet = state/focus/identity details.

Graphite = content.

Final web tokens must come from the real app design system.

## Product assets

Real product behavior must come from the real macOS app.

The site may frame the product but must not fake it.
