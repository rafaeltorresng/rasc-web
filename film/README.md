# Rasc product films — approved production source

Separate Remotion development package. Nothing here is imported by the landing.
The studio exposes only the approved **Complete** (27.9 s) and **Short** (10 s),
1920 × 1080 at 60 composition fps. Web distribution uses the approved 30 fps
Complete in the website's `public/media/`; it is not regenerated by a site build.

## Reproduce

Node 22.13+ or 24+, npm and FFmpeg. From this directory:

```sh
npm ci
npm run lint
npm run verify:native-demo
npm run dev -- --no-open --port=3036
npm run render:native-demo
npm run render:short
```

Render scripts use the installed macOS Chrome path for the verified production
environment. Adapt that explicit executable on another host. Rendering on another
OS may change the system font; these films deliberately use the native Mac font
stack. The scripts export ProRes 4444 masters, H.264/AAC 30/60 fps web versions,
silent alternatives and ending posters to ignored `out/`. Do not copy masters,
source directories or a whole Remotion bundle into the website's public folder.

`src/native-demo` contains the definitive Complete. The selected `v62`/`v63`
modules are shared production dependencies retained at their original paths;
they do not expose old cuts in Studio. Root registration changed, not the edit.

## Selected native source assets

`assets-manifest.json` identifies the exact 1,093 image/audio/metadata files used
by the two frame-driven timelines. The selected PNG/WAV/SVG bytes are versioned
unchanged under `public/`. Total file bytes: 114,591,109; Git deduplicates identical
blobs (73,745,115 unique content bytes). No asset exceeds GitHub's file limit.
This replaces thousands of unused frames, duplicated takes and review exports.
A fresh checkout can render both films without recovering a private archive.

`npm run verify:assets` checks every byte count and SHA-256. The timeline selector
also evaluates all 1,674 Complete frames and 600 Short frames to verify that the
manifest covers the current edit. The native check validates geometry, Retina
limits, character typing, 1× processing/Keep exit, comparison timing and retrieval.

For a new approved capture/edit:

1. Prepare captures using the harness and `scripts/prepare-native-demo.py`.
2. Regenerate procedural sound if needed (`scripts/sound-native-demo.py`; NumPy).
3. `npm run select:assets` writes the manifest and `out/selected-paths.txt`.
4. Review the selection, then from the repository root use
   `git add -f --pathspec-from-file=film/out/selected-paths.txt`.
5. Verify, render and review before replacing public web exports.

New raw/generated `public/` and `sources/` files are ignored by default; selected
tracked assets and provenance remain tracked. Capture preparation requires the
full raw take (Pillow/NumPy); rendering requires only the selected committed set.
Raw takes and historical cuts were preserved in the local production archive,
not deleted or uploaded. Temporary reports and rendered output remain ignored.

## Native harness and honesty

See [native-harness/README.md](native-harness/README.md). It snapshots the native
repository and overlays a Debug-only fixture/provider; it never edits the public
app repository. A separate bundle ID, marked temporary run directory and isolated
synthetic database prevent access to personal notes. Captures use the real native
Scratchpad, Thinking Orb, Preview, Home and Search.

Refine wording and provider wait are scripted. Keep the disclosure **Illustrative
demo · Refine results may vary.** visible beside every published player. The
2.4-second provider wait and 2.8-second unmodified processing footage are editorial,
not a model inference benchmark. Capture, Accept, Keep and retrieval remain actual
native interactions. Home is opened through the native Open Home action; ⌘P is
not represented as a Home shortcut.

Audio is original seeded procedural synthesis; no third-party music or samples.
The existing native Search empty-results transition was retained, not painted out.
